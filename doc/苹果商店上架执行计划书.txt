RAVEN iOS（Apple App Store）上架执行计划书（个人开发者版）
===============================================================================
版本：V1
日期：2026-09-20
适用对象：个人开发者（无公司主体），单人推进

-------------------------------------------------------------------------------
0. 目标与成功标准
-------------------------------------------------------------------------------
目标：
1) 将 RAVEN 交付为可在 iPhone 正常安装、登录、浏览、评论、收藏的应用；
2) 通过 TestFlight 内测；
3) 通过 App Store 审核并可公开下载；
4) 建立可重复执行的发布/回滚流程。

成功标准（Definition of Done）：
- App Store Connect 中应用状态到达“Ready for Distribution”（或已上线）
- 核心路径可用：打开 -> 浏览 -> 详情 -> 评论 -> Echo 回显 -> 收藏
- 关键质量门禁全绿：lint/typecheck/build/test/e2e/audit
- 隐私政策、元数据、截图、版本说明齐全

-------------------------------------------------------------------------------
1. 技术路线与工期建议
-------------------------------------------------------------------------------
推荐路线（长期最稳）：
- React Native + Expo（EAS Build + EAS Submit）

可选路线（最快上线）：
- Capacitor 封装现有 Web

建议（基于你是个人开发者）：
- 若目标是“尽快上架验证市场”：先走 Capacitor；
- 若目标是“长期产品能力和原生体验”：直接走 Expo RN。

本计划默认：
- 采用“先快后稳”策略：先 Capacitor 上线 MVP，再评估 RN 重构窗口。

-------------------------------------------------------------------------------
2. 成本预算（个人开发者）
-------------------------------------------------------------------------------
必须支出：
1) Apple Developer Program：99 USD/年
2) Mac 设备：若已有则 0；若无需购置

可选支出：
1) 域名/隐私政策托管：0 ~ 300 RMB/年
2) 设计素材（图标/截图）：0 ~ 500 RMB
3) 云真机/CI：0 ~ 300 RMB/月

首年预算区间：
- 已有 Mac：约 700 ~ 2000 RMB
- 无 Mac：约 3200 ~ 10000+ RMB

3. 分阶段执行总览（可直接照做）
-------------------------------------------------------------------------------
Phase A：账号与资质准备（0.5~1 天）
Phase B：iOS 工程初始化（1~2 天）
Phase C：移动端适配与能力接入（3~7 天）
Phase D：质量与真机回归（2~4 天）
Phase E：App Store 元数据与合规材料（1~2 天）
Phase F：TestFlight 内测与问题修复（2~5 天）
Phase G：正式提审与上线（1~3 天）
Phase H：上线后 72 小时观测与复盘（3 天）

-------------------------------------------------------------------------------
4. 逐步执行清单（每步有验收）
-------------------------------------------------------------------------------

Step 1（Phase A）：开通苹果开发者账号
执行：
1) 用你的 Apple ID 登录 developer.apple.com
2) 购买 Apple Developer Program（个人）
3) 确保 Apple ID 开启双重认证

验收：
- App Store Connect 可访问
- Membership 状态有效

失败回退：
- 付款失败则更换支付方式；身份信息问题按 Apple 提示补齐

----------------------------------------------------------------------------
Step 2（Phase A）：准备上架基础信息包
执行：
1) 确认应用英文名/副标题/关键词/描述
2) 准备隐私政策 URL（可用现有站点新建页面）
3) 明确支持地区、年龄分级、内容声明

验收：
- 一份完整“上架元数据草稿”可直接粘贴到 App Store Connect

----------------------------------------------------------------------------
Step 3（Phase B）：初始化 iOS 打包工程
执行（Capacitor 路线）：
1) 安装 Capacitor 依赖
2) 生成 iOS 工程并在 Xcode 打开
3) 配置 Bundle ID、Display Name、Version、Build Number

验收：
- App 可在 iOS 模拟器启动
- 能访问现有 RAVEN 页面

----------------------------------------------------------------------------
Step 4（Phase B）：配置签名与证书
执行：
1) 在 Apple Developer/Certificates 创建签名（或 Xcode 自动管理）
2) 在 Xcode 绑定 Team 与 Bundle ID
3) 确认 Archive 不报签名错误

验收：
- 可成功生成 Archive

----------------------------------------------------------------------------
Step 5（Phase C）：移动端能力与行为对齐
执行：
1) 检查登录态持久化（前后台切换/重启）
2) 检查键盘弹起、输入框、滚动、安全区（刘海屏）
3) 检查弱网、离线、超时错误提示
4) 验证你已完成的 a11y 与 touch target 改造在 iOS 生效

验收：
- 核心路径在 iPhone 真机全通过
- 无阻断级 UI/交互 bug

----------------------------------------------------------------------------
Step 6（Phase D）：质量门禁与自动化
执行：
1) 运行：npm run check-all
2) 运行：npm run test:e2e
3) 运行：npm audit --json
4) iOS 真机冒烟：登录、浏览、详情、评论、收藏

验收：
- 门禁全绿
- 真机冒烟通过

----------------------------------------------------------------------------
Step 7（Phase E）：App Store Connect 建应用记录
执行：
1) 新建 App（名称、Bundle ID、SKU）
2) 填写分类、分级、隐私信息
3) 上传图标与截图（6.7/6.5/5.5 至少一套）
4) 填写描述、关键词、版本更新说明

验收：
- 应用记录完整，无红色必填缺失项

----------------------------------------------------------------------------
Step 8（Phase E）：隐私与合规检查
执行：
1) 对照实际能力填写 App Privacy（收集数据项）
2) 若使用第三方登录/追踪，补齐对应声明
3) 准备审核说明（Reviewer Notes）：
   - 如何登录
   - 如何触发核心功能
   - 若功能依赖账号，提供审核测试账号

验收：
- 合规项全部完成

----------------------------------------------------------------------------
Step 9（Phase F）：提交 TestFlight 内测
执行：
1) 上传构建到 App Store Connect
2) 配置内测组（仅你自己也可）
3) 安装 TestFlight 包并做完整回归

验收：
- TestFlight 包可安装可运行
- 至少 1 轮问题修复闭环

----------------------------------------------------------------------------
Step 10（Phase G）：正式提交审核
执行：
1) 选择稳定构建版本
2) 提交 Review
3) 跟踪审核消息并快速响应

验收：
- 审核通过并可上架

常见拒审与处理：
- 2.1 App Completeness：补全不可用按钮或死链
- 5.1 Privacy：补隐私政策、声明实际数据用途
- Login Required：提供可用审核账号/演示路径

----------------------------------------------------------------------------
Step 11（Phase H）：上线后 72 小时观测
执行：
1) 监控崩溃、登录失败率、核心路径转化
2) 收集首批用户反馈
3) 必要时热修/回滚

验收：
- 无 P0 事故
- 留下首发复盘文档

6. 风险与应对
-------------------------------------------------------------------------------
风险 1：没有 Mac
- 应对：先确认硬件；无 Mac 无法完成最终 Xcode 签名提交流程

风险 2：审核被拒
- 应对：提前准备 Reviewer Notes 与测试账号；拒审后 24h 内修复重提

风险 3：移动端交互边界问题
- 应对：真机回归覆盖 iPhone 标准屏 + 刘海屏 + 小屏至少三组
