===============================================================================
RAVEN 基线说明（Baseline Freeze）
===============================================================================
目的：在成熟化改造前，确保当前状态可追溯、可回退。

-------------------------------------------------------------------------------
1. 基线冻结步骤（建议由你手动执行）
-------------------------------------------------------------------------------
1) 检查当前改动
   - 命令：`git status --short`

2) 确认基线标签名称
   - 推荐：`baseline-maturity-2026-09-20`

3) 创建本地 tag
   - 命令：`git tag baseline-maturity-2026-09-20`

4) （可选）推送 tag 到远端
   - 命令：`git push origin baseline-maturity-2026-09-20`

-------------------------------------------------------------------------------
2. 回滚策略
-------------------------------------------------------------------------------
说明：当前仓库有大量未提交内容，成熟化期间避免使用 destructive 命令。

推荐回滚方式：
1) 文档/单文件级回滚：
   - 用 git diff 确认变更范围
   - 按文件逐个恢复（仅恢复确认文件）

2) 提交级回滚：
   - 使用 `git revert <commit>` 生成反向提交
   - 避免 `git reset --hard` 破坏工作现场

3) 数据回滚：
   - 所有 Supabase 迁移必须附回退 SQL 思路
   - 发布前演练“代码回退 + 数据回退”

-------------------------------------------------------------------------------
3. 基线后开发纪律
-------------------------------------------------------------------------------
1) 每个阶段单独分支（建议）
   - `maturity/phase-1-quality-gates`
   - `maturity/phase-2-auth-data-governance` 等

2) 每次变更必须包含
   - 改动说明
   - 验证结果（lint/typecheck/build/test）
   - 风险与回滚说明

3) 禁止事项
   - 未验证直接合并
   - 跨阶段大重构
   - 无文档同步提交
