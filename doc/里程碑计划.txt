===============================================================================
RAVEN 里程碑计划（8 周执行版）
===============================================================================
目标：将 RAVEN 从“可用原型”推进到“成熟可运营应用”
开始日期：2026-09-20

-------------------------------------------------------------------------------
里程碑总览
-------------------------------------------------------------------------------
M0（第 1 周）：基线冻结 + 工程门禁起步
M1（第 2 周）：认证一致性 + 数据治理规范
M2（第 3-4 周）：核心链路稳定性
M3（第 5-6 周）：测试体系成型
M4（第 7 周）：性能与安全收口
M5（第 8 周）：发布运营闭环

-------------------------------------------------------------------------------
M0（第 1 周）
-------------------------------------------------------------------------------
目标：
- 建立项目成熟化“共同语言”和质量底座

任务：
1) 完成审计报告、风险清单、里程碑计划（已完成）
2) 冻结基线（tag + 回滚说明）
3) 新增基础脚本：typecheck/test/check-all（可先最小实现）
4) 搭建 CI 初版

验收指标：
- PR 自动执行 lint + typecheck + build
- 团队有统一 SOP 文档

Cursor 提示词：
"""
请执行 M0 剩余项：
1) 生成基线冻结文档 doc/基线说明.txt（含 tag/回滚命令）
2) 补充 package scripts：typecheck/test/check-all
3) 新增 .github/workflows/ci.yml
4) 输出执行结果与失败项
"""

-------------------------------------------------------------------------------
M1（第 2 周）
-------------------------------------------------------------------------------
目标：
- 认证策略统一，数据变更可控

任务：
1) RequireAuth 接入受保护路由
2) returnTo 行为统一
3) 数据库迁移规范文档与环境数据策略文档
4) RLS 审计报告（至少 reviews/favorites）

验收指标：
- 登录/登出/过期/未验证邮箱路径行为一致
- 数据库操作按 SOP 可复现

Cursor 提示词：
"""
请执行 M1：
1) 接入统一 RequireAuth 到 submit/favorites
2) 统一 returnTo 与登录后回跳
3) 输出 RLS 审计报告（含风险与 SQL 修复建议）
4) 不做 UI 重构，只修一致性问题
"""

-------------------------------------------------------------------------------
M2（第 3-4 周）
-------------------------------------------------------------------------------
目标：
- 核心业务路径稳定，可持续回归

任务：
1) 全链路巡检（Landing->列表->详情->评论->回显->收藏）
2) 修复 P0/P1 缺陷
3) 统一 loading/error/empty 三态
4) 优化 review history N+1 查询

验收指标：
- 核心链路无阻断
- 缺陷复现单全部闭环

Cursor 提示词：
"""
请执行 M2 稳定性整改：
1) 先生成关键路径测试清单
2) 再逐项修复问题并更新 doc/缺陷修复记录.txt
3) 优先修复 review history N+1 查询与错误状态不一致
4) 输出每个问题的复现-修复-验证证据
"""

-------------------------------------------------------------------------------
M3（第 5-6 周）
-------------------------------------------------------------------------------
目标：
- 自动化测试覆盖关键功能

任务：
1) 完整接入 Vitest + RTL
2) 补 services 与核心 UI 的高价值测试
3) 引入 Playwright E2E（登录/评论/收藏/筛选）
4) CI 纳入测试门禁

验收指标：
- 关键服务覆盖率达到目标（建议 70%+）
- 至少 4 条 E2E 稳定通过

Cursor 提示词：
"""
请执行 M3 测试建设：
1) 接入 Vitest + RTL + 覆盖率报告
2) 为 reviews/favorites/auth 写高价值单测
3) 新增 Playwright E2E：登录、评论、收藏、筛选
4) CI 中默认运行单测，E2E 可独立 workflow
"""

-------------------------------------------------------------------------------
M4（第 7 周）
-------------------------------------------------------------------------------
目标：
- 性能与安全指标达到上线要求

任务：
1) 路由懒加载与分包优化
2) 减少不必要重渲染与重复请求
3) 依赖漏洞分级处置
4) 前端安全与 Supabase 权限收口

验收指标：
- 包体和关键交互性能指标有可量化改善
- 高危依赖漏洞处理闭环

Cursor 提示词：
"""
请执行 M4：
1) 路由懒加载、分包、关键列表渲染优化
2) 输出优化前后指标对比（包体/构建/交互）
3) 跑 npm audit 并给出漏洞处理方案（修复或风险接受）
4) 输出安全整改清单
"""

-------------------------------------------------------------------------------
M5（第 8 周）
-------------------------------------------------------------------------------
目标：
- 建立持续发布与运营增长机制

任务：
1) 发布手册与回滚手册
2) 版本号与 changelog 规范
3) 埋点方案与漏斗指标定义
4) 上线后 1 周观察计划

验收指标：
- 团队能按手册独立发版与回滚
- 能回答“访问->评论提交转化率”

Cursor 提示词：
"""
请执行 M5：
1) 输出发布SOP和回滚SOP（代码+数据库）
2) 定义版本策略与 changelog 模板
3) 设计事件埋点与核心漏斗
4) 给出上线后一周巡检表（错误率、性能、转化）
"""

-------------------------------------------------------------------------------
每周固定动作（必须）
-------------------------------------------------------------------------------
1) 周初：锁定本周里程碑范围（不跨阶段）
2) 周中：检查 CI 与缺陷趋势
3) 周末：更新风险分值与下周计划
4) 每次提交：附带验证结果与回滚说明
