===============================================================================
版本：V1
日期：2026-09-20
目标：让 RAVEN 稳定部署到公网，并保证手机端可直接访问与使用。

-------------------------------------------------------------------------------
0. 目标与验收标准
-------------------------------------------------------------------------------
目标：
1) 发布一个公网可访问地址（HTTPS）；
2) 手机浏览器可稳定访问，核心路径可用；
3) 形成可重复执行的发布流程（含回滚）。

验收标准（DoD）：
- 有公网 URL，可在 4G/5G/Wi-Fi 下手机打开
- 核心链路通过：登录 -> 浏览 -> 详情 -> 评论 -> Echo -> 收藏
- `npm run release:rehearsal` 全绿
- 回滚锚点明确（git commit/tag + 发布记录）

-------------------------------------------------------------------------------
1. 发布路线
-------------------------------------------------------------------------------
推荐：Netlify（你仓库当前已具备 Netlify 部署基础）
- 已有 `netlify.toml`
- 已有 release workflow（可手动触发 staging/production）

发布模式：
- 模式 A（最快）：本地 Netlify CLI 手动 deploy（先出公网）
- 模式 B（更规范）：GitHub Actions 手动触发 release workflow（建议长期）

建议执行顺序：先 A 验证可达，再切换 B 固化流程。

-------------------------------------------------------------------------------
2. 执行阶段总览
-------------------------------------------------------------------------------
Phase A：发布前检查（30~60 分钟）
Phase B：创建/绑定 Netlify 站点（20~40 分钟）
Phase C：首次公网发布（20~40 分钟）
Phase D：手机端专项验收（30~60 分钟）
Phase E：回滚与发布固化（20~40 分钟）

-------------------------------------------------------------------------------
3. 详细步骤
-------------------------------------------------------------------------------

Step 1：确认发布前门禁
执行：
1) `npm run check-all`
2) `npm run test:e2e`
3) `npm audit --json`

验收：
- 三项全部通过

失败处理：
- 任一失败不发布，先修复再重跑。

----------------------------------------------------------------------------
Step 2：准备生产环境变量（Netlify）
必须配置：
- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`

建议配置（如有）：
- 其他分析/监控 key（Sentry/Analytics）

验收：
- Netlify Site settings -> Environment variables 已保存

----------------------------------------------------------------------------
Step 3：创建站点并首次部署
方式 A（本地 CLI）：
1) `npx netlify login`
2) `npx netlify init`（选择/创建站点）
3) `npm run build`
4) `npx netlify deploy --prod --dir=dist`

方式 B（GitHub Action）：
1) 在 GitHub Secrets 确认：
   - `NETLIFY_AUTH_TOKEN`
   - `NETLIFY_SITE_ID_STAGING`
   - `NETLIFY_SITE_ID_PRODUCTION`
2) 触发 `.github/workflows/release.yml`，target=production

验收：
- 获得 production URL（https）
- 首页可访问，无 404 重定向问题（SPA 路由正常）

----------------------------------------------------------------------------
Step 4：手机端专项验收（重点）
测试环境：
- iPhone Safari（优先）
- Android Chrome（可选补充）

检查清单：
1) 首屏可打开、无白屏
2) 登录可用，返回路径正确
3) Clubs/Bars 列表筛选可点
4) Detail 页面可加载、失败可重试
5) SubmitReview 可提交
6) Profile Echo 分页可切换
7) Favorites 可切换
8) 暗色主题可读性正常
9) reduced-motion 偏好下动画降级正常

验收：
- 核心路径全通过
- 无 P0/P1 阻塞

----------------------------------------------------------------------------
Step 5：域名（可选）
如你有自定义域名：
1) Netlify 绑定 domain
2) DNS 按提示添加记录
3) HTTPS 证书签发完成

验收：
- 自定义域可访问
- HTTPS 生效

----------------------------------------------------------------------------
Step 6：回滚策略固化
执行：
1) 记录当前上线 commit hash
2) 写入 `doc/上线演练记录.txt` 新增条目
3) 保留上一稳定版本可一键回滚

验收：
- 能说明“回滚到哪个 commit，怎么回”

-------------------------------------------------------------------------------
4. 你需要提供的信息（最少）
-------------------------------------------------------------------------------
必须：
1) 你是否已登录 Netlify（是/否）
2) 是否已有 Netlify 站点（有/无）
3) `VITE_SUPABASE_URL` 与 `VITE_SUPABASE_ANON_KEY` 是否已在 Netlify 配置

可选：
1) 自定义域名（如果要绑定）

-------------------------------------------------------------------------------
5. 风险与应对
-------------------------------------------------------------------------------
风险 1：环境变量没配导致线上白屏或接口失败
- 应对：先 staging 验证，再 production

风险 2：CI 发布成功但页面旧缓存
- 应对：强刷 + Netlify clear cache and redeploy

风险 3：移动端交互边界问题
- 应对：按 Step 4 清单逐项验收，发现即修复再发

-------------------------------------------------------------------------------

Day 2：
- Step 4（手机端专项验收）+ Step 6（回滚固化）
