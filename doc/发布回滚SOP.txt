RAVEN 发布与回滚 SOP（Phase 8）
===============================================================================
日期：2026-09-20

一、发布前检查（必须全部通过）
-------------------------------------------------------------------------------
1) 代码质量门禁
- `npm run lint`
- `npm run typecheck`
- `npm run test`
- `npm run build`
- `npm run test:e2e`

2) 数据与配置检查
- 核对 `.env` 仅包含前端可公开变量（禁止 service_role）
- 若涉及 SQL/migration，先在 staging 完整演练

3) 审核与记录
- 变更清单（功能、修复、风险）
- 回滚点（git tag / commit id）

二、发布流程
-------------------------------------------------------------------------------
1) 合并到主分支（受保护分支策略）
2) CI 全绿后触发部署
3) 部署后执行 smoke checklist：
- 首页可打开
- clubs/bars 列表可加载
- 登录可用
- 受保护路由跳转正常
- 提交评论流程正常

三、故障分级与响应
-------------------------------------------------------------------------------
- P0：核心路径不可用（登录、提交、列表全挂）-> 立即回滚
- P1：部分功能降级但可绕过 -> 30 分钟内评估回滚
- P2：非核心体验问题 -> 记录并排期修复

四、回滚流程
-------------------------------------------------------------------------------
1) 选择最近稳定 tag（或上一版本 commit）
2) 回滚应用版本
3) 若涉及数据库：
- 优先执行前向修复；仅在确认安全时执行回滚脚本
4) 回滚后立刻执行 smoke checklist
5) 发布 incident 复盘记录

五、发布后复盘模板
-------------------------------------------------------------------------------
- 发布版本：
- 发布时间：
- 影响范围：
- 发现问题：
- 根因分析：
- 修复动作：
- 预防措施：

六、GitHub 发布工作流（新增）
-------------------------------------------------------------------------------
工作流文件：
- `.github/workflows/release.yml`

触发方式：
- GitHub Actions -> `Release` -> `Run workflow`
- 选择 `target`:
  - `staging`
  - `production`

执行顺序：
1) `quality-gate`（必过）
   - `npm run check-all`
   - `npm run test:e2e`
   - `npm audit --audit-level=high`
2) 目标环境部署
   - staging: `netlify deploy`
   - production: `netlify deploy --prod`

必需 Secrets：
- `NETLIFY_AUTH_TOKEN`
- `NETLIFY_SITE_ID_STAGING`
- `NETLIFY_SITE_ID_PRODUCTION`

七、推荐发布节奏
-------------------------------------------------------------------------------
1) 先运行 `target=staging`，验证 smoke 与关键路径
2) 验证通过后运行 `target=production`
3) 发布后 15 分钟内重点观察登录、列表、提交评论、收藏守卫
4) 命中 P0/P1 标准即按本 SOP 回滚
