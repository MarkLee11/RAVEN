P0 风险拆解与落地动作
-------------------------------------------------------------------------------
1) R-001（测试缺失）
- 动作：
  - 建立 `test` 脚本与 Vitest 配置
  - 优先覆盖 services（reviews/favorites/auth）
- 验收：
  - 本地可一键运行测试
  - CI 能跑测试且失败可阻断
- Cursor 提示词：
"""
请在 RAVEN 接入 Vitest + React Testing Library，先为 services 写测试：
1) reviewsService 基础成功/失败路径
2) favoritesService 未登录/已登录路径
3) auth 相关 hook/上下文最小测试
并把执行命令、覆盖率结果写入 doc/测试接入记录.txt。
"""

2) R-002（CI 缺失）
- 动作：
  - 新增 `.github/workflows/ci.yml`
  - 执行 lint/typecheck/build/test
- 验收：
  - PR 自动触发检查并可视化结果
- Cursor 提示词：
"""
请新增 GitHub Actions CI 工作流：
触发 push 和 pull_request；
执行 npm ci -> npm run lint -> npm run typecheck -> npm run build -> npm run test。
若项目当前无 typecheck/test 脚本，请先补齐最小实现。
"""

3) R-003（认证策略分散）
- 动作：
  - 引入统一路由守卫组件 RequireAuth
  - 统一未登录跳转 Profile 并保留 returnTo
- 验收：
  - 评论/收藏等受保护页行为一致
- Cursor 提示词：
"""
请实现并接入统一 RequireAuth：
1) submit/favorites 页面受保护
2) 未登录跳转 /profile，并携带 returnTo
3) 登录成功后自动回跳
4) 提供手工测试清单覆盖成功/失败/会话过期
"""

4) R-004（迁移治理）
- 动作：
  - 固化迁移命名规范和执行顺序
  - 区分 dev/staging/prod 数据导入策略
- 验收：
  - 新人按文档可无歧义执行迁移
- Cursor 提示词：
"""
请基于 sql/ 与 supabase/migrations/ 现状，建立统一数据库操作规范：
1) 迁移命名与执行顺序
2) 环境隔离（dev/staging/prod）
3) mock/simple/real 数据导入边界
输出到 doc/数据库操作SOP.txt。
"""
